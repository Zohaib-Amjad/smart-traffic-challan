SMART TRAFFIC CHALLAN SYSTEM
VIVA GUIDE - ROMAN URDU

Yeh guide current implementation ke mutabiq hai. Project FastAPI, SQLite,
OpenCV aur OCR par based local multi-role web application hai. Yeh live CCTV,
real payment gateway ya official police database nahi hai.

============================================================
1. PROJECT KA BASIC IDEA
============================================================

System citizen ko apni vehicle image se number plate aur detail dekhne deta hai.
Traffic Police Officer image recognition, challan generation, payment status aur
history use karta hai. Vehicle Registerer/System Admin vehicle registry manage
karta hai. Public sign-up sirf limited Citizen account banata hai.

Main flow:
Citizen flow: Register, Login, profile update, AI Vehicle Check, image upload,
vehicle detail, linked challans, demo payment, notifications aur dispute submit.
Officer flow: Login, plate recognition, offence select, challan generate, history.
Registrar flow: Login, vehicle registration/update/delete, search, ownership transfer,
document verification aur Active/Suspended/Blocked status sirf registry page par.
Officer registered vehicles dekh kar Issue Challan aur View Fines use karta hai.

============================================================
4. REGISTER AUR LOGIN
============================================================

Register:
URL: /register
API: POST /api/auth/register

Name, email aur password users table mein save hotay hain. Email lowercase hoti
hai. Duplicate email reject hoti hai. Public registration mein Citizen aur
Vehicle Registerer open hain; Traffic Police Officer ke liye allowed_emails
whitelist zaroori hai. Citizen account sirf usi role
mein login kar sakta hai aur uska dashboard sirf apni citizen portal /number-plate
par limited hota hai. Dashboard, vehicle registry, challan generation, reports,
aur officer/admin workflows usay block kar diye gaye hain.

Registration ke baad account seedha database mein save hota hai aur user login
page par redirect hota hai. Email verification code, SMTP setup aur extra
verification step is workflow mein use nahi hotay.

Login aur registration page par special roles ke liye exactly do fixed accounts
hain:
- Traffic Police Officer: officer1@example.com / Officer@1234
- Traffic Police Officer: officer2@example.com / Officer@5678
- Vehicle Registerer: registrar1@example.com / Registrar@1234
- Vehicle Registerer: registrar2@example.com / Registrar@5678
Citizen hi free-form public role hai. Special-role credentials backend bhi enforce
karta hai, sirf browser dropdown par depend nahi karta.

Demo accounts:
- Traffic Police Officer: officer@traffic.gov.pk / admin123
- Traffic Police Officer 2: officer2@traffic.gov.pk / admin123
- Vehicle Registerer/System Admin: admin@traffic.gov.pk / admin123

Citizen registration is public, but built-in demo citizen account is not used as
a default login credential. New citizen users must register and then log in with
that exact account; citizen role is restricted to the citizen portal and cannot
access officer/admin workflows.

Login:
URL: /login
API: POST /api/auth/login

Backend registered email aur password match karta hai. Successful login par
8-hour HttpOnly auth_session cookie set hoti hai. Frontend user object ko
localStorage.currentUser mein rakhta hai. Logout dono values clear karta hai.

If the user tries to log in with an unregistered email, the browser must hand
off to the registration page with that email prefilled. The client fetch shim
must keep the live FastAPI JSON response and only fall back to the local mock
engine when the backend endpoint is actually unreachable.

Passwords Passlib bcrypt hash ke sath stored hotay hain. Signed sessions aur
proper expiry production mein ab bhi zaroori hain.

============================================================
6. VEHICLE MANAGEMENT
============================================================

URL: /vehicles
APIs: GET /api/vehicles, POST /api/vehicles/add

Officer plate, type, make, model, colour, owner name, CNIC, phone, email aur
address save karta hai. Plate uppercase hoti hai. Same plate par record update
hota hai. User records source=user ke sath list mein aate hain.

GET /api/vehicles/{plate_number} registry aur archive search karta hai. Nayi
4+ alphanumeric plate par stable synthetic dummy owner ban sakta hai. Dummy
owner official NADRA record nahi hai.

Current form engine_cc nahi leti. Naye light vehicle ke liye fine lookup mein
1600cc default use ho sakta hai. User vehicles kisi individual officer se
linked nahi hain; sab authenticated officers same user registry dekh sakte hain.

============================================================
7. NUMBER PLATE RECOGNITION
============================================================

URL: /number-plate
API: POST /api/simulate/process_image

Pipeline:
1. OpenCV upload decode karta hai.
2. Archive image filename/hash se match hoti hai.
3. XML box archive plate crop provide karta hai.
4. Normal image mein Haar Cascade aur contour detection hoti hai.
5. Multiple vehicles ya plates par random choice nahi hoti.
6. Crop resize, contrast aur threshold se preprocess hota hai.
7. Tesseract OCR text read karta hai.
8. EasyOCR fallback available hai.
9. Text clean aur validate hota hai.
10. Owner aur ticket status lookup hota hai.

Frontend 10 seconds tak wait karta hai. Results:
- Plate text: readable single plate.
- Not found: readable plate nahi mili.
- Multiple vehicles detected: multiple regions milay.

NPR khud challan issue nahi karta. Officer Generate Challan page par ticket
complete karta hai. Archive mein 433 images aur Pascal VOC XML boxes hain.

============================================================
8. PUNJAB FINE SCHEDULE
============================================================

File: backend/app/punjab_schedule.py
API: GET /api/challans/schedule?vehicle_type=&engine_cc=
Law reference: Twelfth Schedule, Provincial Motor Vehicles Ordinance, 1965

25 offences V-01 se V-25 tak hain. 5 fine columns:
1. Motorcycle
2. Three-wheeler
3. Motorcar/Jeep under 2000cc
4. Motorcar/Jeep over 2000cc
5. PSV, Carrier, HTV, Tractor, Trailer

Fine offence aur vehicle class se calculate hota hai. Is liye same offence ka
motorcycle aur car amount different ho sakta hai. Kuch offences N/A hotay hain.
Frontend N/A option disable karta hai aur backend bhi reject karta hai.

Backend user ke typed fine par trust nahi karta. Violation code aur vehicle
class se lookup_fine() amount dobara calculate karta hai.

============================================================
9. CHALLAN GENERATION
============================================================

URL: /generate-challan
API: POST /api/challans/generate

Officer plate, offence, location aur due date deta hai. Backend:
1. Registered session user check karta hai.
2. Vehicle type aur engine_cc read karta hai.
3. Offence applicability check karta hai.
4. Punjab schedule se fine calculate karta hai.
5. Past due date reject karta hai.
6. challans table mein status Unpaid ke sath record save karta hai.
7. /challan/{id} open hota hai.

Request fields: vehicle_number, violation_code, location, due_date, issued_by.

============================================================
10. CHALLAN HISTORY AUR TICKET
============================================================

History URL: /challans
API: GET /api/challans?issued_by={current_user_id}

History current officer ki tickets show karti hai. Search, status filter, view
aur delete available hain.

Ticket URL: /challan/{id}
Status: PATCH /api/challans/{id_or_no}/status
PDF: GET /api/challans/{challan_no}/pdf
QR: GET /api/challans/{challan_no}/qr

Ticket par plate, owner, offence, location, amount, dates aur legal details
show hoti hain. Mark as Paid database status ko Paid karta hai. Yeh payment
simulation hai; bank ya JazzCash gateway nahi hai. PDF ReportLab se aur QR
qrcode library se banta hai.

============================================================
11. REPORTS
============================================================

URL: /reports
APIs: GET /api/reports/summary, GET /api/reports/csv

Reports system-wide hain, per-user nahi. challans table se values aati hain:
- Total challans = COUNT(*)
- Total fine = SUM(fine_amount)
- Paid fine = status Paid wali SUM
- Unpaid fine = Paid ke ilawa SUM
- Paid/unpaid counts = status filters
- Violation Summary = violation_name GROUP BY count
- Recent Challans = newest 10 rows

CSV report saari challans export karti hai.

============================================================
12. DATABASE
============================================================

File: backend/traffic_challan.db

Tables:
- users: registered login accounts

- cameras: camera metadata

Users registration se create hotay hain. Challans authenticated workflow se
create hotay hain. Startup users ya sample challans seed nahi karta.

15. LIMITATIONS
============================================================

1. Passwords bcrypt hash ke sath save hotay hain.
2. Session cookie simple user ID rakhti hai.
3. Legacy APIs ko complete server authorization ki zaroorat hai.
4. Reports global hain, history per issuer hai.
5. User vehicles officer ownership se linked nahi hain.
6. OCR blur, glare, angle aur poor lighting mein fail ho sakta hai.
7. Dummy owner synthetic data hai.
8. Live CCTV aur real payment gateway available nahi.
9. SQLite local FYP ke liye hai, large production cluster ke liye nahi.

============================================================
16. COMMON VIVA QUESTIONS
============================================================

Q: FastAPI kyun?
A: Fast REST API, validation aur Swagger /docs deta hai.

Q: SQLite kyun?
A: Serverless aur local FYP demo ke liye simple hai.

Q: OCR kya karta hai?
A: Plate image ke characters ko text mein convert karta hai.

Q: Multiple vehicles par result reject kyun?
A: Galat vehicle select hone se bachne ke liye.

Q: Fine amount form se change kyun nahi hota?
A: Backend violation code aur vehicle class se amount lookup karta hai.

Q: History aur Reports mein farq?
A: History current issuer ki; Reports database ki saari tickets ki.

Q: Payment real hai?
A: Nahi. Mark as Paid simulation hai.

Q: Unknown plate par owner kyun milta hai?
A: 4+ characters par stable synthetic dummy owner banta hai.

Q: Authentication production-ready hai?
A: Nahi. Hashing, signed sessions, API authorization aur ownership checks
production se pehle add karne honge.
